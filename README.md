# Static React portfolio / پورتفولیوی React

پورتفولیوی استاتیک React با مخزن Git مستقل.
این پروژه به بک‌اند، دیتابیس یا API نیاز ندارد.
تمام اطلاعات پروفایل، مهارت‌ها، پروژه‌ها و تصاویر، نمایشی و محلی هستند.

## اجرا

Node.js نسخه ۲۲٫۱۲ یا جدیدتر لازم است (نسخه ۲۴ پیشنهاد می‌شود).
دستورهای زیر را از ریشه همین مخزن اجرا کنید:

```powershell
npm ci
npm run dev
```

آدرس محلی در خروجی نمایش داده می‌شود؛ معمولاً `http://127.0.0.1:5173`.

## ویرایش محتوا

- `src/data/portfolio.js`: نام، معرفی، مهارت‌ها، پروژه‌ها، لینک‌ها و مسیر رزومه.
- `src/data/translations.js`: متن‌های رابط فارسی و انگلیسی.
- `public/images/`: تصاویر نمونه‌کارها؛ SVGهای فعلی تصویرهای نمایشی ساخته‌شده برای این نسخه‌اند.
- `public/resume.txt`: رزومه نمونه؛ با رزومه خودتان جایگزین و مسیر `profile.resume` را اصلاح کنید.
- `src/styles.css` و `tailwind.config.js`: ظاهر و رنگ‌بندی.

با اضافه کردن یک پروژه به آرایه `projects`، صفحه جزئیات آن خودکار در
`/#/projects/your-project-slug` ایجاد می‌شود. برای نمایش کارت در صفحه اصلی،
`featured` را `true` قرار دهید. مقدار `slug` هر پروژه باید یکتا باشد.

لینک‌های GitHub، LinkedIn و ایمیل پیش‌فرض `null` هستند؛ پس از قرار دادن مقدار واقعی
نمایش داده می‌شوند. اطلاعات این نمونه درباره یک فرد واقعی یا سابقه کار تأییدشده نیست.

## امکانات

- صفحه اصلی با خدمات، مهارت‌ها، پروژه‌ها، درباره من و تماس.
- جزئیات هر پروژه، قابلیت‌ها، تصاویر و پروژه‌های مرتبط؛ صفحه 404 برای مسیر نامعتبر.
- فارسی و انگلیسی، راست‌چین، حالت روشن و تاریک با حفظ تنظیمات در مرورگر.
- منوی موبایل، ناوبری با صفحه‌کلید و رعایت کاهش حرکت.
- فونت‌های بسته‌بندی‌شده؛ بدون CDN یا درخواست API در زمان استفاده.
- فرم تماس فقط اعتبارسنجی و پیش‌نمایش انجام می‌دهد؛ هیچ پیامی ارسال یا ذخیره نمی‌شود.
  اطلاعات فرم فقط تا زمانی که همان صفحه باز است در حافظه قرار دارد.

## ساخت نسخه انتشار

```powershell
npm run build
npm run preview
```

خروجی پوشه `dist` شامل فایل‌های استاتیک آماده انتشار است. نیازی به سرور برنامه نیست.
فایل `dist/index.html` را با دوبار کلیک اجرا نکنید؛ برای مشاهده محلی از دستور preview
و برای دسترسی عمومی از یک میزبان استاتیک مانند GitHub Pages استفاده کنید.

## انتشار روی GitHub Pages

Workflow مستقل در `.github/workflows/pages.yml` در ریشه همین مخزن قرار دارد.
فقط خروجی استاتیک `dist` منتشر می‌شود. وابستگی‌ها، کش‌ها و فایل‌های محیطی
در Git نادیده گرفته می‌شوند. هنوز remote تنظیم نشده و سایت آنلاین منتشر نشده است.

1. یک مخزن خالی و جداگانه در GitHub بسازید؛ آن را با README یا فایل‌های اولیه
   مقداردهی نکنید، چون این مخزن از قبل اولین commit و شاخه `main` دارد.
2. از ریشه همین مخزن، آن را به آدرس واقعی مخزن جدید وصل کنید. مقدار نمونه زیر
   را با آدرس خودتان جایگزین کنید:

```powershell
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

3. در GitHub، مسیر **Settings → Pages → Build and deployment → Source**
   را باز کنید و **GitHub Actions** را انتخاب کنید.
4. از تب **Actions**، Workflow با نام **Publish React portfolio to GitHub Pages**
   را انتخاب و **Run workflow** را روی `main` اجرا کنید. برای انتشارهای بعدی،
   هر push به `main` خودکار تست، ساخت و انتشار را انجام می‌دهد.

تست‌ها و بررسی مسیر انتشار قبل از Deploy اجرا می‌شوند؛ با شکست هرکدام، نسخه جدید
منتشر نمی‌شود. مسیر پایه سایت از تنظیمات Pages گرفته می‌شود تا آدرس‌های فایل‌ها
در مخزن پروژه‌ای، سایت کاربری یا دامنه سفارشی درست باشند.

آدرس سایت معمولاً `https://USERNAME.github.io/REPOSITORY/` خواهد بود.
استفاده از مسیرهای hash باعث می‌شود صفحه پروژه‌ها بعد از رفرش نیز درست کار کند.

راهنمای رسمی: [GitHub Pages با Workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
و [انتشار Vite روی Pages](https://vite.dev/guide/static-deploy.html).

## بررسی

```powershell
npx playwright install chromium
npm test
```

آزمون‌ها تغییر زبان و پوسته، مسیرهای پروژه و رفرش، اعتبارسنجی فرم و پیش‌نمایش،
منوی موبایل و نبود درخواست شبکه خارجی را بررسی می‌کنند.

برای بررسی خروجی نهایی در یک زیردایرکتوری مشابه GitHub Pages:

```powershell
npm run build
npm run check:build
```

این بررسی به `dist` آماده و مرورگر Chromium نصب‌شده توسط Playwright نیاز دارد.
تصاویر بررسی در پوشه نادیده‌گرفته‌شده `.verification` قرار می‌گیرند.

برای بازسازی تصاویر نمایشی پس از ویرایش اسکریپت:

```powershell
node scripts/generate-demo-assets.mjs
```
